Especificación modular para un proyecto de Ingeniería de Software. Cada Skill es un módulo independiente con contrato público (API, eventos y estado) y puede implementarse, probarse y desplegarse por separado.

Estructura de carpetas (por Skill, "feature-sliced"):

src/
  app/                  # bootstrap, router, providers
  ui/                   # design system: Button, Modal, Toast, Skeleton, Slider
  components/           # componentes compartidos (TrackRow, AlbumCard, ArtistCard)
  features/
    player/  search/  lyrics/  playlists/  artist/  timeline/  album/
    library/  favorites/  history/  recommendations/  queue/  discovery/
      ├── ui/           # componentes de la feature
      ├── hooks/
      ├── store/        # slice de estado
      ├── services/     # lógica de aplicación
      └── api/          # cliente HTTP de la feature
  domain/               # entidades, value objects, reglas puras (sin React ni HTTP)
  services/             # audio engine, analytics, storage
  api/                  # cliente HTTP base, interceptores, DTOs
  utils/                # formatTime, debounce, normalizeText

Reglas de dependencia (Clean Architecture): ui → features → domain; domain no importa nada externo; services y api implementan interfaces (puertos) definidas en domain. Una feature nunca importa componentes internos de otra: se comunica por su índice público (features/x/index.ts) o por eventos.

Principios: SRP (un hook/servicio = una responsabilidad), DRY (TrackRow, MediaCard, useInfiniteList compartidos), Open/Closed (estrategias de recomendación y de ordenamiento intercambiables), Dependency Inversion (el player depende de la interfaz AudioEngine, no de HTMLAudioElement).

Convenciones de API: prefijo /api/v1, JSON, paginación por cursor (?limit=&cursor=), errores con formato { "error": { "code", "message", "details" } }, IDs UUID v7.

Skill: 01 — Music Player

Objetivo

Proveer el reproductor principal (mini y full) con control completo de reproducción y una máquina de estados robusta.

Funcionalidades

  • Play/Pause, Previous/Next, seek bar, volumen, mute.
  • Tiempo actual / duración total.
  • Autoplay al terminar (siguiente en cola), Repeat (off/all/one), Shuffle.
  • Mini-player fijo inferior y Full player (pantalla completa).
  • Cambio de pista sin cortes: se reutiliza un único elemento de audio y se precarga la siguiente pista.
  • Estados visibles de loading, buffering, error y playing.
  • Media Session API (controles del sistema y teclas multimedia).
  • Atajos: Space play/pause, ←/→ ±5 s, ↑/↓ volumen, M mute.

User Flow

  1. El usuario pulsa play en una canción, álbum o playlist.
  2. El sistema construye la cola (Skill 12) y establece currentTrack.
  3. Estado LOADING → se resuelve URL de stream → PLAYING.
  4. Si la red se interrumpe: BUFFERING; si falla: ERROR con opción de reintentar/saltar.
  5. Al terminar: ENDED → según repeat/cola, avanza o queda en IDLE.

Componentes

MiniPlayer, FullPlayer, PlayerControls, SeekBar, VolumeControl, TimeLabel, NowPlayingInfo, PlayerErrorBanner, AudioEngine (servicio), MediaSessionAdapter.

Estado

Máquina de estados finita:

IDLE ──load()──▶ LOADING ──canplay──▶ PLAYING ◀──play()── PAUSED
                    │                   │  ▲                 ▲
                    │                   │  └─canplay─┐       │pause()
                    │                   ▼            │       │
                    │              BUFFERING ────────┘       │
                    │                   │                    │
                    └────error─────────▶ ERROR ◀──error──────┘
PLAYING ──ended──▶ ENDED ──next()/repeat──▶ LOADING | IDLE

Transiciones válidas (todas las demás se ignoran y se registran en debug):

Desde Evento Hacia
IDLE LOAD LOADING
LOADING CAN_PLAY PLAYING (si autoplay) / PAUSED
PLAYING PAUSE PAUSED
PAUSED PLAY PLAYING
PLAYING WAITING BUFFERING
BUFFERING CAN_PLAY PLAYING
cualquiera FAIL ERROR
PLAYING ENDED ENDED
ERROR RETRY / NEXT LOADING
ENDED NEXT / REPEAT LOADING / IDLE

El estado vive únicamente en Skill 14; el player solo despacha eventos y renderiza.

Datos

Track { id, title, durationMs, streamUrl, artworkUrl }, posición de reproducción (currentTime), preferencias (volume, muted, repeatMode, shuffle) persistidas en localStorage.

API

  • GET /tracks/:id/stream → { url, expiresAt, format, bitrate } (URL firmada de corta vida).
  • PUT /me/playback → guarda { trackId, positionMs, queueId } (Skill 10/14, reanudar).

Reglas de negocio

  • Al cambiar de pista, currentTime se reinicia a 0.
  • "Previous" tras >3 s de reproducción reinicia la pista; antes de 3 s va a la anterior.
  • Repeat one ignora Next automático pero no Next manual.
  • Una reproducción cuenta como "escucha" desde 30 s o 50 % de la pista (lo que ocurra primero).
  • Un solo audio activo: iniciar reproducción en otro dispositivo/pestaña pausa la actual (BroadcastChannel / WebSocket).

Casos de error

  • URL de stream expirada → renovar una vez de forma silenciosa.
  • Pista no disponible (404/región) → toast + saltar a la siguiente tras 2 s.
  • NotAllowedError por autoplay bloqueado → mostrar botón "Tocar para reproducir".
  • Pérdida de red → BUFFERING con reintento exponencial (3 intentos) → ERROR.

Dependencias

Skill 14 (estado), 12 (cola), 10 (historial), 03 (letras, escucha currentTime), 15 (layouts).

Consideraciones técnicas

  • AudioEngine implementa play/pause/seek/setVolume/load/preload/on(event); permite mock en tests.
  • Actualizar currentTime con requestAnimationFrame a ~4 Hz para la UI, no en cada timeupdate.
  • Precarga: cuando quedan <20 s, preload(nextTrack) en un segundo elemento de audio (crossfade opcional, Skill adicional).
  • Accesibilidad: role="slider", aria-valuenow, foco visible, aria-live="polite" para cambios de pista.

Criterios de aceptación

  • Todas las transiciones de la tabla se cubren con tests unitarios.
  • Cambio de pista en <300 ms percibidos con la siguiente precargada.
  • Controles del sistema (teclas multimedia, pantalla de bloqueo) funcionan.
  • Un error de red nunca deja la UI en LOADING indefinido (timeout 10 s).
  • Accesible por teclado y lector de pantalla.

Skill: 02 — Music Search

Objetivo

Búsqueda instantánea, tolerante a errores y unificada para canciones, artistas, álbumes y playlists.

Funcionalidades

  • Autocomplete y resultados instantáneos mientras se escribe.
  • Historial y búsquedas recientes (borrar una / todas).
  • Filtros por tipo, género, año, duración, explícito.
  • Ordenamiento: relevancia, popularidad, fecha, alfabético.
  • Tolerancia a errores ortográficos y búsqueda parcial/prefijo, sin importar tildes ni mayúsculas.
  • Resultados agrupados ("Mejor resultado", Canciones, Artistas, Álbumes, Playlists).
  • Estado vacío con sugerencias.

User Flow

  1. El usuario enfoca la barra (/ como atajo) → se muestran búsquedas recientes.
  2. Escribe → tras 250 ms de debounce se piden sugerencias.
  3. Presiona Enter o elige una sugerencia → página /search?q= con secciones y filtros.
  4. Reproduce, abre artista/álbum o añade a playlist desde el resultado.

Componentes

SearchBar, SuggestionList, RecentSearches, SearchResultsPage, ResultSection, FilterChips, SortMenu, EmptySearchState, TopResultCard.

Estado

query, debouncedQuery, filters, sort, status (idle | loading | success | empty | error), recent[]. Resultados en la caché de TanStack Query con clave ['search', q, filters, sort].

Datos

SearchHistory { id, userId, query, createdAt }; índice de búsqueda con campos normalizados (title_norm, artist_norm, album_norm).

API

  • GET /search?q=&type=track,artist,album,playlist&genre=&year=&sort=&limit=&cursor= → resultados agrupados con topResult.
  • GET /search/suggest?q= → hasta 8 sugerencias { text, type, id }.
  • GET /me/search-history, POST /me/search-history, DELETE /me/search-history[/:id].

Reglas de negocio

  • Mínimo 2 caracteres para sugerencias.
  • Query normalizada: minúsculas, sin acentos, trim, espacios colapsados.
  • Ranking = coincidencia textual (0.5) + popularidad (0.3) + afinidad del usuario (0.2).
  • El historial guarda máximo 50 entradas; se deduplican.
  • Playlists privadas de otros usuarios nunca aparecen.

Casos de error

  • Sin resultados → mensaje "No encontramos «xyz»" + sugerencia de corrección ("¿Quisiste decir…?") + acceso a Discovery.
  • Fallo de red → estado de error con reintento; se mantienen los últimos resultados.
  • Query maliciosa/larga (>100 chars) → 400 con mensaje claro.

Dependencias

Skill 01 (reproducir), 04 (añadir a playlist), 05/07 (navegación), 11 (afinidad), 15 (layout móvil).

Consideraciones técnicas

  • MVP: PostgreSQL pg_trgm + unaccent + índices GIN; similarity() para typos; ILIKE 'q%' para prefijo.
  • V2: Meilisearch/OpenSearch con typo tolerance nativa.
  • Cancelar peticiones obsoletas con AbortController; cachear sugerencias 60 s.
  • Resaltar coincidencias en el texto (escapando HTML).

Criterios de aceptación

  • Sugerencias en <200 ms p95 con 100 k canciones.
  • "Bad Buny" devuelve Bad Bunny; "cold pla" devuelve Coldplay.
  • Nunca se dispara una petición por cada pulsación de tecla.
  • Estados vacío, error y carga implementados y probados.

Skill: 03 — Lyrics

Objetivo

Mostrar letras, sincronizadas por línea cuando existan timestamps.

Funcionalidades

  • Letra estática o sincronizada (formato LRC).
  • Resaltado de la línea actual, scroll automático suave.
  • Scroll manual que pausa el auto-scroll; botón "Sincronizar" para volver.
  • Tocar una línea sincronizada hace seek a ese instante.
  • Estado alternativo si no hay letra.
  • Ajuste de tamaño de fuente; vista completa en móvil.

User Flow

  1. Al cambiar de pista se solicita la letra.
  2. Si synced: la línea activa se calcula según currentTime.
  3. Si el usuario hace scroll, aparece "Volver a sincronizar".
  4. Si no hay letra: "Letra no disponible" + opción "Sugerir letra" (futuro).

Componentes

LyricsPanel, LyricsLine, LyricsEmptyState, ResyncButton, useActiveLine (hook), parseLrc (util).

Estado

lyrics, status, activeLineIndex (derivado, no almacenado), isAutoScroll.

Datos

Lyrics { id, trackId, language, isSynced, source, copyright }, LyricsLine { id, lyricsId, index, startMs, endMs?, text }.

API

  • GET /lyrics/:trackId → { trackId, isSynced, language, lines:[{index,startMs,text}], source } o 404.

Reglas de negocio

  • La línea activa es la última con startMs <= currentTime + offset.
  • Sin timestamps: mostrar texto plano sin resaltado.
  • Respetar licencias: campo source y copyright visibles en el pie.
  • Offset manual por pista (±2 s) opcional.

Casos de error

  • 404 → estado vacío (no es error).
  • LRC malformado → fallback a letra plana y log.
  • Salto de seek grande → recalcular con búsqueda binaria.

Dependencias

Skill 14 (currentTime, currentTrack), 01, 15.

Consideraciones técnicas

  • Búsqueda binaria O(log n) para línea activa; solo re-renderizar cuando cambie el índice.
  • scrollIntoView({ behavior:'smooth', block:'center' }) con detección de scroll del usuario por wheel/touchmove.
  • Cachear letras por trackId (24 h).
  • Sanitizar texto (nunca dangerouslySetInnerHTML).

Criterios de aceptación

  • Desfase visual <150 ms respecto al audio.
  • Resincronizar funciona tras scroll manual y tras seek.
  • Sin letra se muestra estado alternativo, sin errores en consola.

Skill: 04 — Playlist Manager

Objetivo

CRUD completo de playlists con reordenamiento, visibilidad y uso compartido.

Funcionalidades

Crear, editar (nombre, descripción, portada), eliminar, duplicar; añadir/quitar canciones; reordenar con drag & drop; pública/privada; compartir por enlace; mostrar nº de canciones y duración total; modal "Añadir a playlist".

User Flow

  1. "Nueva playlist" → se crea con nombre por defecto y se abre su vista.
  2. Desde cualquier TrackRow → menú "⋯" → "Añadir a playlist" → modal con lista + "Crear nueva".
  3. Arrastrar filas para reordenar (con alternativa de teclado).
  4. Compartir: copiar enlace /playlist/:id (solo si es pública o con token).

Componentes

PlaylistPage, PlaylistHeader, PlaylistTrackList (virtualizada + sortable), AddToPlaylistModal, PlaylistForm, CoverUploader, ShareDialog, PlaylistCard.

Estado

Servidor: TanStack Query (['playlists'], ['playlist', id]). Local: orden optimista durante el drag; mutaciones con rollback.

Datos

Playlist { id, ownerId, name, description?, coverUrl?, isPublic, createdAt, updatedAt }, PlaylistTrack { playlistId, trackId, position, addedAt, addedBy }.

API

  • GET /playlists (propias) · POST /playlists {name, description?, isPublic?} · GET /playlists/:id
  • PUT /playlists/:id (parcial: nombre, descripción, visibilidad) · DELETE /playlists/:id
  • POST /playlists/:id/tracks { trackIds:[], position? } · DELETE /playlists/:id/tracks/:trackId
  • PATCH /playlists/:id/tracks/order { trackId, newPosition }
  • POST /playlists/:id/duplicate · POST /playlists/:id/cover (multipart)
  • POST /playlists/:id/share → { url, token? }

Reglas de negocio

  • Solo el dueño edita/elimina. Playlists públicas son de solo lectura para terceros.
  • Nombre 1–100 caracteres; descripción ≤ 300.
  • Se permite repetir una canción, pero se avisa ("Ya está en esta playlist").
  • Límite de 10 000 canciones por playlist.
  • Posiciones contiguas 0..n-1; reordenar recalcula en una transacción.
  • Portada por defecto: mosaico de las 4 primeras carátulas.

Casos de error

403 (no es dueño), 404 (playlist eliminada), 409 (conflicto de orden concurrente → refrescar), 413/415 (portada >5 MB o tipo inválido), pérdida de red durante drag → rollback + toast.

Dependencias

Skill 01/12 (reproducir/encolar), 08 (biblioteca), 02, 15.

Consideraciones técnicas

  • Drag & drop con dnd-kit (accesible por teclado).
  • Reordenamiento con posiciones densas en transacción, o LexoRank/fractional indexing si hay alta concurrencia.
  • Duración total calculada por SUM y cacheada en columna denormalizada.
  • Portadas: validar MIME real, redimensionar en servidor, servir por CDN.

Criterios de aceptación

  • Crear, editar, eliminar y duplicar con feedback por toast.
  • Reordenar persiste tras recargar; funciona con teclado.
  • Un usuario no puede modificar playlists ajenas (test de autorización).
  • Listas de 1 000+ pistas se desplazan fluidas (virtualización).

Skill: 05 — Artist Profile

Objetivo

Perfil completo y navegable de cada artista o grupo.

Funcionalidades

Cabecera (nombre, imagen, oyentes mensuales, seguir), biografía, género, país, inicio de carrera, canciones populares, discografía (álbumes, singles, colaboraciones), artistas relacionados, botón reproducir/aleatorio.

User Flow

  1. El usuario abre /artist/:id desde búsqueda, tarjeta o pista.
  2. Ve canciones populares y puede reproducir el top.
  3. Alterna pestañas: Discografía · Sobre el artista · Trayectoria (Skill 06).
  4. Sigue al artista o abre uno relacionado.

Componentes

ArtistPage, ArtistHero, PopularTracks, DiscographyTabs, AlbumGrid, RelatedArtists, ArtistBio, FollowButton.

Estado

Caché de servidor ['artist', id]; UI local: pestaña activa y "ver más".

Datos

Artist { id, name, imageUrl, bio, country, careerStartYear, isGroup, verified }, relación con Genre, ArtistRelation, miembros (si es grupo).

API

  • GET /artists/:id · GET /artists/:id/albums?type=album|single|compilation|appears_on
  • GET /artists/:id/top-tracks · GET /artists/:id/related · GET /artists/:id/collaborations

Reglas de negocio

  • Popularidad = reproducciones ponderadas por recencia (últimos 90 días).
  • Discografía ordenada por fecha descendente; separada por tipo.
  • Colaboraciones = pistas donde figura como artista secundario.
  • Biografía en varios idiomas con fallback a español/inglés.

Casos de error

Artista inexistente → 404 con página "No encontramos este artista"; sin biografía → bloque oculto; imagen rota → avatar con iniciales.

Dependencias

Skill 07, 06, 09 (seguir), 01, 11 (relacionados).

Consideraciones técnicas

Cargar cabecera + top tracks primero (skeleton), discografía por lazy loading; imágenes srcset + WebP/AVIF; caché CDN 10 min; datos de artistas relacionados precomputados por job nocturno.

Criterios de aceptación

  • Todos los campos requeridos visibles o con estado alternativo.
  • LCP <2.5 s en 4G simulada.
  • Seguir/dejar de seguir refleja el cambio de inmediato (optimista).

Skill: 06 — Artist Career / Timeline

Objetivo

Visualizar la trayectoria del artista como una línea temporal moderna e interactiva.

Funcionalidades

  • Hitos: inicio de carrera, primer lanzamiento, álbumes clave, cambios de estilo, colaboraciones relevantes, premios, eventos importantes.
  • Filtros por tipo de hito y por década.
  • Gráfico de "evolución musical" (géneros/atributos de audio por época).
  • Cada hito enlaza a álbum, canción o fuente; botón "escuchar esta época".
  • Vista vertical (móvil) y horizontal con scroll (desktop).

User Flow

  1. En el perfil, pestaña "Trayectoria".
  2. Se muestra la línea con hitos agrupados por año; el usuario filtra por tipo.
  3. Abre un hito → tarjeta con descripción, imagen y acciones (reproducir, ir al álbum).
  4. Explora la evolución musical con un gráfico de áreas por género/energía.

Componentes

CareerTimeline, TimelineNode, TimelineFilters, MilestoneCard, EraPlayButton, StyleEvolutionChart, AwardBadge.

Estado

Servidor ['artist', id, 'timeline']; local: filtros, hito seleccionado, zoom.

Datos

CareerEvent { id, artistId, type (start|release|album|style_change|collab|award|event), date, datePrecision (year|month|day), title, description, relatedAlbumId?, relatedTrackId?, relatedArtistId?, sourceUrl?, imageUrl? }. Métricas de estilo: ArtistEraStat { artistId, year, genreWeights JSONB, avgEnergy, avgValence, avgTempo }.

API

  • GET /artists/:id/timeline?type=&from=&to= → hitos ordenados.
  • GET /artists/:id/evolution → series por año.
  • (Admin) POST/PUT/DELETE /admin/artists/:id/timeline.

Reglas de negocio

  • Orden cronológico ascendente; hitos sin día exacto se ubican por precisión declarada.
  • Los lanzamientos se generan automáticamente desde Album/Track; los demás son editoriales.
  • Premios y eventos requieren sourceUrl para publicarse.
  • Cambios de estilo solo se muestran si hay ≥2 años de datos.

Casos de error

Sin hitos → estado vacío "Aún no tenemos la trayectoria completa"; datos inconsistentes (fecha futura) → excluidos y registrados; fallo de gráfico → se muestra solo la línea.

Dependencias

Skill 05, 07, 01; fuente de datos editorial/API externa (MusicBrainz, Wikidata).

Consideraciones técnicas

SVG/CSS con IntersectionObserver para animar entrada; virtualizar si >200 hitos; gráfico con D3 o Recharts; respetar prefers-reduced-motion; importación de datos vía job que combina catálogo propio + MusicBrainz/Wikidata con revisión editorial.

Criterios de aceptación

  • Hitos ordenados y filtrables; funciona en móvil y desktop.
  • Cada hito enlaza a su entidad relacionada cuando existe.
  • Animaciones desactivadas con prefers-reduced-motion.

Skill: 07 — Album Explorer

Objetivo

Consultar álbumes con toda su información y reproducirlos.

Funcionalidades

Portada, nombre, artista, año, género, nº de canciones, duración, lista de pistas (por disco), créditos/info, canciones más reproducidas, guardar álbum, reproducir/aleatorio, más del artista.

User Flow

Abrir /album/:id → ver cabecera → reproducir o elegir pista → guardar en biblioteca → navegar al artista.

Componentes

AlbumPage, AlbumHeader, TrackList (con TrackRow), AlbumInfoPanel, TopTracksBadge, MoreByArtist.

Estado

Caché ['album', id]; local: disco expandido, orden de pistas.

Datos

Album { id, title, artistId, releaseDate, type, genreId, coverUrl, label?, totalTracks, durationMs }, Track { albumId, discNumber, trackNumber }.

API

  • GET /albums/:id · GET /albums/:id/tracks · GET /albums?artistId=&type=&sort=
  • PUT /me/library/albums/:id · DELETE /me/library/albums/:id

Reglas de negocio

  • Pistas ordenadas por (discNumber, trackNumber).
  • Duración total = suma de pistas; nº de pistas derivado.
  • "Más reproducidas" = top 5 por reproducciones globales de los últimos 90 días.
  • Pistas no disponibles se muestran atenuadas y se omiten al reproducir.

Casos de error

Álbum 404; pista sin audio → marcada "No disponible"; portada rota → placeholder.

Dependencias

Consideraciones técnicas

Criterios de aceptación

  • Reproduce el álbum completo y el orden respeta discos.
  • Guardar/quitar del catálogo personal es inmediato.

Skill: 08 — User Library

Objetivo

Centralizar el contenido personal del usuario.

Funcionalidades

Pestañas: Playlists, Álbumes, Artistas, Canciones favoritas, Historial, Descargas (si aplica). Búsqueda dentro de la biblioteca, ordenar (reciente, alfabético, artista), vista lista/cuadrícula, carpetas de playlists (V2).

User Flow

Sidebar → "Tu biblioteca" → elegir pestaña → filtrar/ordenar → reproducir o abrir elemento.

Componentes

LibraryPage, LibraryTabs, LibraryFilterBar, LibraryGrid/List, LibraryEmptyState, DownloadsManager (V3).

Estado

Caché por pestaña con paginación infinita; filtros y vista en localStorage.

Datos

Agregación de Playlist, Favorite, Follow, ListeningHistory; Download { userId, trackId, status, sizeBytes, storedAt } (cliente, IndexedDB).

API

  • GET /me/library?type=playlists|albums|artists|tracks&sort=&q=&cursor=
  • GET /me/library/summary → contadores.
  • Descargas (V3): POST /me/downloads, DELETE /me/downloads/:trackId.

Reglas de negocio

  • Todo el contenido es privado al usuario.
  • Las descargas requieren sesión vigente y verificación periódica (cada 30 días) de licencia.
  • Eliminar una playlist de la biblioteca ≠ eliminar canciones del catálogo.

Casos de error

Biblioteca vacía → CTA a Discovery; contenido retirado del catálogo → elemento marcado "No disponible" con opción de quitar; cuota de almacenamiento excedida (descargas) → aviso.

Dependencias

Skill 04, 09, 10, 07, 05, 01.

Consideraciones técnicas

Endpoint agregado para evitar N peticiones; descargas con Service Worker + Cache Storage/IndexedDB y audio cifrado (MVP: fuera de alcance, documentado como V3); virtualización en colecciones grandes.

Criterios de aceptación

  • Todas las pestañas cargan con paginación y estados vacío/error.
  • Búsqueda y orden funcionan sin recargar.
  • Contadores coinciden con el contenido real.

Skill: 09 — Favorites

Objetivo

Gestionar "me gusta", álbumes guardados y artistas seguidos, sincronizados entre dispositivos.

Funcionalidades

Marcar/desmarcar canción (❤), guardar álbum, seguir artista, listar favoritos, sincronización multi-dispositivo, playlist automática "Canciones que te gustan".

User Flow

Skill: 14 — Audio State Manager

Objetivo

Fuente única de verdad del estado global del reproductor.

Funcionalidades

Manejar currentTrack, queue, currentTime, duration, volume, isPlaying, repeatMode, shuffle, buffering, loading, error; exponer acciones y selectores; sincronizar pestañas/dispositivos.

User Flow

Cualquier componente despacha acciones (play, seek…); el store actualiza el estado; AudioEngine reacciona y notifica eventos que vuelven como acciones. Flujo unidireccional.

Componentes

playerStore (Zustand), playerMachine (transiciones), AudioEngine, selectores (selectIsPlaying, selectProgress), PlayerSyncService.

Estado

Estado primario (no derivable):

type PlayerState = {
  status: 'IDLE'|'LOADING'|'PLAYING'|'PAUSED'|'BUFFERING'|'ERROR'|'ENDED';
  currentTrackId: string | null;
  queue: QueueState;            // ver Skill 12
  currentTime: number;          // segundos
  duration: number;
  volume: number; muted: boolean;
  repeatMode: 'off'|'all'|'one';
  shuffle: boolean;

};

Derivados (selectores, no se guardan): isPlaying = status==='PLAYING', isBuffering, isLoading, currentTrack (por id desde la caché de entidades), progress = currentTime/duration.

Datos

Persistencia parcial en localStorage: volume, muted, repeatMode, shuffle, queue, lastPosition.

API

  • currentTime se actualiza en un slice separado con suscripción selectiva para no re-renderizar todo.
  • Toda transición pasa por playerMachine.
  • currentTrack guarda solo el ID; los datos completos viven en la caché de entidades (normalización).

Casos de error

Transición inválida → ignorada + log; estado corrupto en localStorage → reset seguro a IDLE; desincronización entre pestañas → gana la pestaña "líder" (Web Locks / BroadcastChannel).

Dependencias

Base de Skill 01, 03, 10, 12, 15.

Consideraciones técnicas

Selectores con shallow equality; subscribeWithSelector; tests con motor de audio simulado; DevTools habilitado en desarrollo; evitar useEffect para sincronizar estados derivados.

Criterios de aceptación

  • Ningún estado duplicado (auditoría de código).
  • La barra de progreso re-renderiza solo su componente.
  • Recargar la página restaura cola y preferencias.

C. Seguridad

  • Autenticación: contraseñas con Argon2id; access token JWT de 15 min (claims mínimos: sub, role, jti) + refresh token opaco de 30 días en cookie HttpOnly; Secure; SameSite=Lax, rotado en cada uso con detección de reutilización. MFA opcional (V2). OAuth (Google/Apple) como mejora.
  • Autorización: RBAC (user, editor, admin) + verificación de propiedad por recurso (playlist.ownerId === user.id) en un guard/policy reutilizable; denegar por defecto.
  • Protección de endpoints: guards globales; rutas públicas listadas explícitamente; CORS restringido a orígenes conocidos; CSRF mitigado con SameSite + cabecera personalizada en mutaciones.
  • Validación de entradas: esquemas (Zod/class-validator) en cada endpoint; listas blancas de campos de ordenamiento; límites de tamaño y longitud; IDs validados como UUID.
  • Rate limiting (Redis, sliding window): login 5/min/IP+email; búsqueda 60/min/usuario; escrituras 120/min; /history por lote; bloqueo temporal progresivo.
  • XSS: React escapa por defecto; prohibido dangerouslySetInnerHTML (letras y biografías se renderizan como texto o Markdown sanitizado con DOMPurify); CSP estricta (default-src 'self', img-src CDN, sin unsafe-inline); X-Content-Type-Options, Referrer-Policy.
  • SQL Injection: consultas parametrizadas / ORM (Prisma, TypeORM); nunca concatenar SQL; el rol de BD de la aplicación sin privilegios DDL.
  • Manejo seguro de archivos: portadas y avatares: validar MIME real (magic bytes), máx. 5 MB, re-encode (elimina metadatos y payloads), nombre generado (UUID), almacenamiento fuera del webroot, antivirus opcional; audio servido por URL firmada de corta duración, sin listado de bucket.
  • Control de permisos de contenido: playlists privadas no indexables; enlaces de compartir con token revocable.
  • Privacidad: cumplimiento de GDPR/Ley 1581 (Colombia): consentimiento, exportación y eliminación de datos, pausar historial.
  • Operación: secretos en variables/secret manager, dependencias auditadas (npm audit, Dependabot), logs sin datos sensibles, HTTPS + HSTS, backups cifrados.

A1 — Crossfade y Audio Avanzado

  9. Mejoras futuras: audio espacial, EQ automático por auriculares.

A2 — Radio / Estaciones Inteligentes

  1. Objetivo: reproducción infinita a partir de una semilla.
  2. Problema: al terminar la cola el usuario debe buscar más música.
  3. Funcionalidades: radio por canción/artista/género, autoplay al acabar la cola, ajuste "más familiar / más descubrimiento".

  7. Dependencias: 11, 12, 01.
  8. Complejidad: Media.
  9. Mejoras futuras: radio contextual (hora/actividad), DJ con voz IA.

A3 — Modo Offline y Descargas (PWA)

  1. Objetivo: escuchar sin conexión.
  2. Problema: dependencia de red estable.
